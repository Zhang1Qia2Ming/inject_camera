# PCIe Debug Regression Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复新增 ILA/VIO 后旧镜像可枚举而新镜像无法建立 PCIe 链路的回归，同时保留不依赖 XDMA 时钟的 JTAG 诊断能力。

**Architecture:** 用 PS `pl_clk0` 驱动 ILA/VIO。新增 `pcie_diag` 模块，在 XDMA `axi_aclk` 域生成 Gray 计数心跳并同步到 `pl_clk0`，同时采集 `pcie_rst_n` 与 `user_lnk_up`。ILA 不再连接 XDMA 数据域或 PCIe 参考时钟树，VIO 输出在 `lane_inject` 内同步后才控制 fsync 覆盖。

**Tech Stack:** Verilog 2001、Vivado 2020.2 Block Design/Tcl、XSim、Zynq UltraScale+、XDMA PCIe Gen3 x4。

## Global Constraints

- 只通过 JTAG 下载验证，确认前不替换 SD 卡 `BOOT.bin`。
- 不修改 XDMA IP 配置、三路 H2C、VDMA、MIPI 数据路径和 BSP 库。
- 不进行 PCIe 热插拔。
- 不提交 Git。

**Files:**

**Interfaces:**

- `dbg_bus[47:32]`: 保留为 0
- `dbg_bus[31:16]`: 同步后的 XDMA 时钟 Gray 计数
- `dbg_bus[15:11]`: `pcie_rst_n`、复位释放记录、`user_lnk_up`、参考时钟活动、XDMA 时钟活动

- [ ] **Step 1: 写测试平台**

测试平台提供持续运行的 `dbg_clk`，先停止 `axi_aclk`，再启动它；依次释放 `pcie_rst_n` 和置位 `user_lnk_up`。断言 XDMA 心跳在启动前不变化而启动后变化、状态位能被同步捕获。

- [ ] **Step 2: 运行测试并确认因模块缺失而失败**

Run:

```bash
source /data/xilinx/Vivado/2020.2/settings64.sh

```

Expected: FAIL because `pcie_diag.v` does not exist.

- [ ] **Step 3: 实现最小诊断模块**

XDMA 时钟域使用自由运行二进制计数器并转换为 Gray 码；`pl_clk0` 域使用带 `ASYNC_REG` 属性的双级寄存器同步。状态信号同样双级同步，活动位通过比较相邻采样置位。

- [ ] **Step 4: 同步 VIO 控制输入**

在 `lane_inject.v` 的 `h2c_clk` 域增加两级同步寄存器，`s2mm_fsync` 只使用同步后的 VIO enable/value，避免 `pl_clk0` 到 XDMA 域的直接异步控制。

- [ ] **Step 5: 运行 XSim**


**Files:**
- Modify: `inspect_inject_debug.tcl`
- Use: `program_inject_debug.tcl`

- [ ] **Step 1: JTAG 下载新 bit**

不改变 SD 卡 BOOT，只对 FPGA 下载实现后的 bit。

- [ ] **Step 2: 验证独立 ILA**

- [ ] **Step 3: 验证 PCIe**

检查根端口为 Gen3 x4，重扫后存在 `10ee:9034`，恢复动态桥窗口和 COMMAND，再确认 BAR+`0x2000`=`0x1fc20006`、BAR+`0x3000`=`0x1fc30006`。

- [ ] **Step 4: 决策**

若 JTAG 新 bit 能枚举，回归修复成立，再决定是否打包 BOOT；若不能枚举，使用独立 ILA 的四类信号定位参考时钟、PERST#、XDMA 时钟或链路状态，不覆盖旧 BOOT。
